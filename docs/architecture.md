# BotOS — システムアーキテクチャ仕様書

## 1. 全体構造

BotOSは以下の3つの主要コンポーネントで構成される。

```text
+--------------------------------------------------------------+
| Web Panel (Next.js / TypeScript)                             |
| - Blockly (Scratch風) / Monaco Editor                        |
| - Marketplace (無料プラグイン共有)                           |
| - ギルド管理・設定画面                                        |
+------------------------------+-------------------------------+
                               |
                               | REST API / WebSocket
                               v
+--------------------------------------------------------------+
| BotOS API Gateway (FastAPI / Python)                         |
| - 認証・認可 (Discord OAuth2 / JWT)                          |
| - プラグインメタデータ・JSON管理                             |
| - ギルド別設定・上限申請管理                                 |
+------------------------------+-------------------------------+
                               |
                               | 内部通信 (Redis Pub/Sub or gRPC/IPC)
                               v
+--------------------------------------------------------------+
| BotOS Core Engine (discord.py)                               |
| - Discord Gateway 接続                                       |
| - ギルド別スラッシュコマンド動的同期 (Guild Sync)             |
| - プラグイン実行エンジン & サンドボックス                     |
| - イベントディスパッチャ (on_message, on_member_join 等)      |
+--------------------------------------------------------------+
```

## 2. コンポーネント間連携フロー

### 2.1 プラグイン保存・同期フロー
1. 管理者がWebパネル上でBlocklyブロックを配置、またはコードを記述。
2. Webパネルから `POST /api/guilds/{guild_id}/plugins/{plugin_id}` へJSON定義を送信。
3. API GatewayがDBへ保存し、Core Engineへ内部通信（Redis / IPC）経由で「同期要求イベント」を発行。
4. Core Engineが対象ギルドのコマンド総数を算出（標準上限30件チェック）。
5. Core EngineがDiscord APIに対してギルドコマンド同期 (`bot.tree.sync(guild=...)`) を実行。
6. 完了結果（成功/失敗）をWebSocket経由でWebパネルへ即座に通知。

### 2.2 コマンド実行フロー
1. ユーザーがDiscord上でスラッシュコマンドを実行。
2. Core Engineがインタラクションを受信。
3. ギルドIDとコマンド名から該当するプラグインとハンドラを特定。
4. サンドボックス環境（Sandbox Runner）を起動し、安全なラッパー経由で処理を実行。
5. 実行結果をDiscordへレスポンス。実行ログ・エラーログをDB/キャッシュへ蓄積。
