# BotOS — サンドボックス仕様書

ユーザー定義コード（Blockly生成コード、Python）をホスト環境から隔離して安全に実行するための仕様。
※ MVPランタイムは Python 3.11+ (discord.py) を対象とし、Node.js等のマルチランタイム対応は将来フェーズで検討。

## 1. セキュリティ方針
プラグインコードは完全に「信頼できない任意の入力」として扱う。ホスト環境のファイルシステム、ネットワーク、他テナントのメモリ空間への直接アクセスを遮断する。

## 2. 段階的制限モデル

### 2.1 MVP (フェーズ1) の実装スコープ
- **実行制限 (Timeout):** 1コマンド/イベントあたり最大3.0秒（`asyncio.wait_for` による非同期タイムアウト）。超過時は処理中断し、Discord側にタイムアウトを返却。
- **AST事前検証:** コード登録・保存時にPython AST（抽象構文木）を解析し、危険なbuiltins参照や未許可インポート・eval/execが含まれている場合は保存を拒否。
- **ラッパーコンテキスト分離:** 生の `discord.py` インスタンスを渡さず、公開プロパティを絞った制限コンテキストオブジェクトのみを注入。

### 2.2 製品版 (フェーズ2) の実装スコープ
- **リソース制限 (cgroups / コンテナ):** 1実行コンテキストあたり最大64MBメモリ上限、CPUクォータ設定。
- **完全プロセス分離:** 各プラグイン実行を専用の軽量サンドボックスワーカー（コンテナまたはseccompプロセス）へ隔離。
- **レート制限:** ギルドごとに1分あたりの外部アクション（メッセージ送信・編集など）回数を制御。

### 2.3 システムコール・モジュール制限 (Python)
- **禁止モジュール:** `os`, `sys`, `subprocess`, `socket`, `ctypes`, `threading`, `multiprocessing`, `importlib` など。
- **許可モジュール:** `math`, `random`, `json`, `datetime`, `re` および `botos` 公式ラッパーのみ。

## 3. ラッパーオブジェクト設計
サンドボックス内からは、生のdiscord.pyインスタンスではなく、権限と安全性が担保されたラッパーオブジェクトのみを公開する。

- `ctx`: コマンドコンテキスト（`author`, `channel`, `guild`, `reply()`, `defer()`）
- `guild`: ギルド情報（`id`, `name`, `get_channel()`, `get_member()`）
- `member`: メンバー情報（`id`, `name`, `roles`, `kick()`, `ban()`, `add_role()`）
- `channel`: チャンネル情報（`id`, `name`, `send()`）
- `storage`: プラグイン専用のKey-Value永続化ストレージ（ギルド別データ保存用）
