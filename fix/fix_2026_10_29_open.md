# 設定画面 (/settings) UI簡素化計画 (2026-10-29)

## 目的
`/settings` の設定画面が実装詳細をそのまま露出していて、一般的な設定画面というより「デバッグ/システム情報パネル」に見えている。
「AIっぽくて無駄が多い」と感じる原因を整理し、ユーザーが触れる設定だけに絞った自然で落ち着いた画面にする。

## 現状分析

`web/app/settings/page.tsx` を見ると以下の問題がある。

### 問題点

- **内部実装の露出**: 「詳細（ランタイム・システム環境）」に `BotOS Core v0.1.0-alpha` / `Python 3.14 (AsyncIO / FastAPI)` / `http://localhost:8000` / `SQLite (WAL Mode) / JSON Schema` などの実行環境・構成をそのまま表示している
- **開発者向け仕様書そのもの**: 「詳細（AST 実行セキュリティ規約）」に `Import`/`ImportFrom`/`Exec`/`Global` 禁止ノードや `__builtins__` 等の遮断属性、`500ms` タイムアウトまで羅列している
- **意味の薄いトグル**: 「サンドボックス強制モード」が `disabled` かつ説明的な文言のみで、ユーザーが操作できない上に強調されすぎている
- **情報密度過多**: アイコン（`Cpu`, `Code2`, `ShieldCheck`, `Server`, `Database`, `Info` 等）を多用し、各項目が小さく詰め込まれて視覚的にノイズが多い
- **セクション構造が不自然**: 「全般設定」「詳細（ランタイム・...）」「詳細（AST 実行セキュリティ規約）」という命名で、設定画面としての階層が曖昧

### 根本原因
「何が設定できるか」ではなく「今どうなっているか（システム状態）」を説明してしまっているのがAI生成感の主因だと考える。

## 修正方針

1. **設定可能な項目のみに絞る**  
   ユーザーが実際に切り替えられるもの（例: `コマンド自動同期`）だけを残す。状態表示は原則として削除。

2. **システム情報は隠蔽/移設**  
   ランタイムやAPIエンドポイント、ストレージ層といった内部情報は設定画面から撤去する。必要であれば別ページ（例: `/debug` や `/about`）に隔離するか、完全に非表示にする。

3. **セキュリティ仕様の露出を避ける**  
   ASTガードの細かな仕様はエンドユーザーには不要。セキュリティ上の事実（「保護有効」程度）すら必要最小限にするか、表示自体をやめる。

4. **文言・見た目を簡素化**  
   長く説明的な日本語を要約し、無駄なアイコン・装飾・太字の羅列を減らす。Next.js + Tailwind の落ち着いたニュートラルなトーンに寄せる。

## 具体的な修正案

### 削除対象
- `詳細（ランタイム・システム環境）` セクション全体（BotOS Core / Python / API Gateway / Storage 層）
- `詳細（AST 実行セキュリティ規約）` セクション全体（禁止ノード・遮断属性・タイムアウト等）

### 残す/調整対象
- **全般設定**  
  - `コマンド自動同期`: 説明文を短縮（例: 「Discordスラッシュコマンドを自動で登録する」程度に）し、必要なら文言をより自然にする
  - `サンドボックス強制モード`: 操作不可な上に情報過多なので、表示自体を削除。将来的に設定可能になるまで出さないのが無難

### 追加検討（任意）
- 設定項目が増える見込みがなければ、セクション見出し自体も「設定」のみなど最小限にする
- 余白（`space-y`）を調整して圧迫感を落とす

## 実装手順

1. **現状確認** - `web/app/settings/page.tsx` の構造・import を再確認（不要になった `Cpu/Code2/Server/Database/Info/ShieldCheck` 等のアイコンimportも整理）
2. **編集** - 上記方針に沿ってセクション削除・文言短縮・レイアウト簡素化
3. **表示確認** - `cd web && npm run dev` 等で `/settings` を目視確認し、違和感が減ったかチェック
4. **Lint/型チェック** - `npm run lint` / `tsc --noEmit`（可能なら）で破綻がないか確認
5. **コミット** - 意図が分かりやすいメッセージでコミット（例: `refactor(web): simplify settings page to user-configurable items only`）

## 検証基準

- [ ] `/settings` に内部バージョン・ポート・ストレージ詳細が一切表示されていない
- [ ] AST仕様の箇条書きが消えている
- [ ] ユーザーが操作できるトグル/設定のみが目立っている
- [ ] 前より「AIが自動生成した管理画面」ではなく「普通の設定画面」に見える
- [ ] 既存の機能（コマンド自動同期等）に副作用がない
- [ ] ビルドエラー・型エラーなし

## 補足
設定画面は「説明」より「設定」に徹するのが正解。システムの中身を知りたい人はREADMEやログを見るので十分。
